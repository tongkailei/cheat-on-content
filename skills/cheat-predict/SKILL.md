# Cheat-Predict：盲预测

**核心原则：预测必须在看到任何真实数据之前写完，写完后 immutable。**

---

## 前置检查

1. **确认 .cheat-state.json 存在**：不在则路由到 `cheat-init`
2. **确认有最终稿**：用户需要提供草稿路径，或从 `scripts/` 目录选取
3. **确认没有看过数据**：用户不能先透露实际播放量

---

## 模式判断

读取 `.cheat-state.json` 的 `mode`：

- **cold-start**（< 5 个校准样本）：简化预测
  - 7 维打分 + 一句话 bet
  - 不强求具体 bucket 数字

- **calibration**（≥ 5 个样本）：完整预测
  - 7 维打分 + 预测播放量 bucket + 信心指数 + 锚点对比

---

## 预测步骤

### Step 1：获取草稿

用户说"启动预测"后，询问草稿路径。

如果用户没说，列出 `scripts/` 目录下的文件供选择。

### Step 2：打分（如未打分）

检查用户是否刚做过评分：
- 如果有 recent score 数据，直接用
- 如果没有，调用 `cheat-score` 先打分

### Step 3：分析内容

读取草稿内容，分析：
- 话题类型（新闻评论/知识科普/个人表达/热点追踪/...)
- 目标受众
- 时效性
- 与同类已发布内容的差异点

### Step 4：写预测

#### Cold-Start 预测格式

```markdown
# 预测：<标题>

## 元信息
- 日期：<YYYY-MM-DD>
- 阶段：predictions
- 模式：cold-start
- 草稿路径：<path>

## 预测

**一句话 bet**：<核心假设，1-2 句话>

**信心指数**：<low / medium / high>

**锚点**：<与哪个已知视频/账号类似>

**预期表现**：<简单描述预期>
- 最好情况：<描述>
- 最坏情况：<描述>

## 评分（cheat-score 输出）
<!-- 引用打分结果 -->

## 复盘（待 T+3d 填写）
- 实际播放量：（待回收）
- 预测偏差：（待分析）
- rubric 偏差：（待评估）
- 新观察：（待补充）
```

#### Calibration 预测格式

```markdown
# 预测：<标题>

## 元信息
- 日期：<YYYY-MM-DD>
- 阶段：predictions
- 模式：calibration
- 草稿路径：<path>

## 预测

**预测播放量 bucket**：
- 保守：<bucket 1>
- 基准：<bucket 2>
- 乐观：<bucket 3>

**信心指数**：<low / medium / high>
（含义：low=靠直觉，medium=有参考数据，high=高度确定）

**锚点对比**：
| 维度 | 本稿 | 锚点视频 |
|---|---|---|
| 钩子强度 | <x/10> | <y/10> |
| ... | ... | ... |

**一句话 bet**：<核心假设，1-2 句话>

## 评分（cheat-score 输出）
<!-- 引用打分结果 -->

## 复盘（待 T+3d 填写）
- 实际播放量：（待回收）
- 预测偏差：（待分析）
- rubric 偏差：（待评估）
- 新观察：（待补充）
```

---

## Step 5：保存预测文件

文件命名：`predictions/YYYY-MM-DD_<id>_<short-title>.md`

- 从草稿文件名提取 `<id>` 和 `<short-title>`
- 如果草稿不在 `scripts/` 目录，用当前日期生成

写入预测内容到文件。

---

## Step 6：更新 .cheat-state.json

```json
{
  "lastUpdated": "<当前时间>",
  "lastPrediction": "<预测文件路径>",
  "buffer": {
    "count": <+1>,
    "items": [<新增项>]
  }
}
```

同时更新 STATUS.md 的 Buffer 区域。

---

## Step 7：输出

```
✅ 预测已保存！

📁 文件：<预测文件路径>
🎯 一句话 bet：<核心假设>
📊 综合得分：<分数> (<等级>)

⏰ 拍完后说"拍了"或"录完了"
📢 发布后说"已发布"
📅 T+3d 后说"复盘"
```

---

## 拒绝场景

如果用户说「帮我预测但先告诉你播放量你来反推」：
→ 拒绝。这是重建构预测，不是盲预测。
→ 告知正确的流程：先写预测，再发布，再复盘。

## 预测播放量 Bucket 参考

| Bucket | 范围（参考） | 说明 |
|---|---|---|
| L1 | < 1万 | 起步期，正常 |
| L2 | 1-10万 | 中等，有传播 |
| L3 | 10-50万 | 不错，算法青睐 |
| L4 | 50-100万 | 优秀，热点加持 |
| L5 | 100-500万 | 爆款，现象级 |
| L6 | > 500万 | 顶流，极小概率 |

> Bucket 是校准数据积累后才会准确。cold-start 阶段不要强求对应关系。
