# Cheat-Retro：T+3d 复盘

回收真实数据，对比预测与实际，分析偏差，更新 rubric。

---

## 前置检查

1. **确认 .cheat-state.json 存在**：不在则路由到 `cheat-init`
2. **确认有待复盘的预测**：查找 `predictions/` 中有"发布时间"但无"实际数据"的文件
3. **确认已过 T+3d**：发布时间距今 ≥ 3 天

---

## Step 1：确定要复盘的内容

用户可能说：
- "复盘" → 列出所有待复盘的预测文件
- "复盘 <标题>" → 找到对应预测文件
- "复盘 <path>" → 直接用指定路径

如果没有待复盘内容，告知用户。

---

## Step 2：收集真实数据

需要收集的数据：

| 数据项 | 说明 | 来源 |
|---|---|---|
| 播放量 | 核心指标 | 平台后台/视频页 |
| 点赞数 | 互动指标 | 平台后台/视频页 |
| 评论数 | 互动质量 | 平台后台/视频页 |
| 转发/分享数 | 传播指标 | 平台后台/视频页 |
| 完播率（如有） | 内容质量 | 平台后台 |
| 负面评论特征 | 改进信号 | 评论区 |

询问用户：
```
📊 复盘需要真实数据

请提供以下数据（从平台后台或视频页获取）：

1. 播放量（必填）：
2. 点赞数：
3. 评论数：
4. 转发/分享数：
5. 其他观察（如有）：

或者直接发发布链接，我帮你抓取。
```

---

## Step 3：尝试自动抓取（可选）

如果用户提供了发布链接，尝试用 `web_fetch` 或 `web_search` 抓取数据。

支持的平台（尽力而为，不保证成功）：
- 抖音/抖音火山版
- B站（bilibili）
- 视频号
- 小红书
- YouTube

如果抓取失败，提示用户提供数据。

---

## Step 4：读取预测文件

找到对应的预测文件，对比：

```
预测播放量：<bucket>
实际播放量：<真实数据>

预测偏差分析：
- 高估了还是低估了？
- 偏差幅度多大？
```

---

## Step 5：更新预测文件

追加到 `## 复盘` 段：

```markdown
## 复盘

### 真实数据
- 回收时间：<YYYY-MM-DD>
- 播放量：<真实数字>
- 点赞：<数字>
- 评论：<数字>
- 转发：<数字>
- 其他观察：<文字>

### 预测偏差
- 预测 vs 实际：<分析>
- 偏差原因：<推测原因>

### Rubric 偏差
- 哪个维度打分偏高/偏低？
- 维度权重是否需要调整？

### 新观察
- 从这次学到了什么？
- 有什么 pattern 想加入 rubric_notes.md？
```

---

## Step 6：判断是否触发 Bump

检查校准池是否有 ≥ 5 个有完整复盘数据的样本：

- **是** → 询问用户是否要"升级 rubric"（cheat-bump）
- **否** → 更新 .cheat-state.json 的 `calibration.totalSamples++`

---

## Step 7：更新 .cheat-state.json

```json
{
  "lastUpdated": "<当前时间>",
  "calibration": {
    "totalSamples": <+1>,
    "lastRetroAt": "<当前时间>"
  }
}
```

如果这是第 5 个样本，触发模式切换为 `calibration`：

```json
{
  "mode": "calibration"
}
```

---

## 输出

```
📊 复盘完成：<标题>

🎯 预测：<bucket> → 实际：<数字>
📈 偏差：<高估/低估> <百分比>

💡 关键洞察：
<1-3 条学到的 pattern>

📝 已更新：<预测文件路径>
🔄 rubric 观察笔记已追加

<如果 ≥ 5 个样本>：
⚡ 校准池已有 5+ 样本，可以"升级 rubric"解锁完整预测
```

---

## 注意事项

- **不修改 ## 预测段**（immutable）
- 只追加到 ## 复盘段
- 如果用户跳过 T+3d 随时复盘也可以，但数据可能不稳定（算法还在推送中）
- 复盘数据会积累到 rubric_notes.md 的观察笔记中，用于后续 bump
